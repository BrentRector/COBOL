# PB3028 — the redesign is judged by the same instrument that found the problem

**Why:** the owner authorized the pipeline redesign on measurements (kb/Work PB3015; evidence
`docs/rearchitecture/evidence/fleet-optimization/2026-10-11-pipeline-measurement-2026-10-10.md`). `train_measure.py`
records trains (clusters, first_run, fixed_in_train, attribution_min, population_runs); after PB3023/PB3024 there are no
trains, so the instrument must follow the pipeline or the before/after comparison is lost (CLAUDE.md rule 5: pair the
change with the measurement that keeps it honest).

**Design:** `DESIGN-test-build-ci.md` §3.17.5 (last bullet).

## What changes
1. `scripts/orchestrator/landing_measure.py record --branch <b> --pr <n> --done <ISO> --review-clean <ISO> --enqueued
   <ISO> --merged <ISO> --bounces <n> --bounce-causes <text> --ci-wall-s <s> --local-gate-s <s>`; `enqueue.py` writes the
   record it can (DONE from the report, enqueued now, local gate seconds from `verdict.json`); the `enqueue` unit
   completes it from `gh pr view --json mergedAt,mergeQueueEntry,statusCheckRollup` and the workflow run's timings.
2. `summary`: changes landed per hour, median and p90 minutes DONE → on main, bounces per landing and their causes
   (cluster defect · load/timing · conflict · infrastructure), merge-group CI wall, local gate minutes per landing; and
   the SAME figures from `train-measurements.jsonl` and PB3015's evidence as the "before" column.
3. `train_measure.py` and `train-measurements.jsonl` retire from the write path (rule 4); the historical file is read by
   `summary` for the before column and frozen under `evidence/fleet-optimization/` with the first after-summary.
4. The ledger (`gen_ledger.py`) shows the summary's headline (landed per hour, minutes per landing) in place of the train
   trend.

## Landed (wave 1062 C2)
`scripts/orchestrator/landing_measure.py` replaced `train_measure.py` (deleted with `TrainMeasureDriftTests`; its drift
sweep `LandingMeasureDriftTests.TheRetiredTrainWriter_IsDeleted_AndNothingNamesIt` keeps every tracked file off it).
- **Record:** one JSON object per pull request in `<coord>/landing-measurements.jsonl`, built by patches (`record`), the
  FIRST enqueue time kept, stamps checked in order DONE, review clean, enqueued, merged. `enqueue.py queue` writes the
  record it can the moment the PR is queued (DONE = the newest implementer report naming the branch and written before
  the queue; local gate seconds = the sum of the worktree's `verdict.json` `timings.wall_s`); a record that cannot be
  written is a loud warning, never a failed landing. `--changes N` counts a lander train's clusters.
- **`complete`** reads `mergedAt`, the count of FAILED merge-group runs of the PR (bounces; a run GitHub cancelled
  because an earlier entry failed is a ripple, not a bounce) and the successful run's wall from `gh`. Not probed live:
  no merge group has run yet (the ruleset is ABSENT), so the `gh-readonly-queue/main/pr-<n>-<sha>` branch shape is
  GitHub's documented one; `complete` prints a warning when a merged PR matches no successful run, and the first
  `summary` after the first queued landing is the live check.
- **`summary`** prints the AFTER column (changes landed per hour, median and p90 minutes DONE to main, bounces per
  landing with causes cluster-defect, load-timing, conflict, infrastructure and UNATTRIBUTED, merge-group CI wall, local
  gate minutes) beside the BEFORE column (the retired train records, batched gating: 1.53 changes/h over 25 trains and
  136 changes at this writing, minutes per landed change from lander start to push as a floor, ejections as the bounce
  analogue; the frozen 2026-10-10 evidence's 41 % gate and 16.5 % push-main + CI shares, each figure re-checked against
  the evidence file by the self-test). A field never observed prints UNMEASURED. `freeze` copies the train records and
  the first after-summary under `evidence/fleet-optimization/` once a PR has landed (not yet run: there is no landing).
- **Ledger:** `gen_ledger.py` shows `landing_measure.landing_rate_input` (the queue's own rate and median minutes per
  landing from two landings, else the trains') in its estimate inputs, and `ledger_plan.estimate_inputs` divides by it.
- **Interim:** a landing through `push-main.sh` (the queue not ACTIVE) writes no record; the train file is the BEFORE column.
